## 🤖 สำหรับ AI Agent

**อ่าน [`AGENTS.md`](AGENTS.md) ก่อนทำงาน** — มีกฎเหล็กที่ถ้าไม่อ่านจะทำให้รายงานผิด

สรุปสั้น ๆ:

1. **ห้ามสรุปว่า "คอลัมน์ไม่มีจริง" โดยไม่แก้ขอบเขต (scope)** — `[X]` ภายใน `SELECT(Tbl[...])`
   หมายถึงคอลัมน์ของ `Tbl` ไม่ใช่ตารางที่สูตรอยู่ · `[_THISROW].[X]` = ตารางตัวเอง ·
   `[RefColumn].[X]` = ตารางที่ Ref ชี้ไป · ถ้าไม่แก้ scope ทุกความต่างด้านเคสจะดูเหมือนบั๊ก
2. **เคส ≠ ช่องว่าง** — `Startdate` ≠ `StartDate` คือ error จริง (Appsheet แยกเคสชื่อคอลัมน์)
   แต่ `Shipment No` ≠ `ShipmentNo` ยืนยันจาก PDF ไม่ได้ ต้องระบุว่า *"ต้องยืนยันในแอป"*
3. **ทุกข้อค้นพบต้องมี** `table` + `column` + `property` + หน้า PDF + `falsifiable_test`
   (อะไรจะพิสูจน์ว่าคุณผิด — ถ้าเขียนไม่ได้ แปลว่ายังไม่พร้อมส่ง)
4. **อย่าวิเคราะห์ซ้ำ** — อ่าน `analysis/findings/000-baseline-quality.json` ก่อน

เริ่มงานได้เลย:

```bash
# 1) ดูว่ามีอะไรบ้าง
cat app/index.json | head -60

# 2) เปิดตารางที่สนใจ (ดูคอลัมน์ 'file' ใน index ก่อน)
cat app/tables/main/03.json

# 3) ตรวจว่าสิ่งที่จะส่งผ่านเกณฑ์
python3 scripts/validate_findings.py analysis/findings/<ไฟล์ของคุณ>.json
```

มีงานให้เลือก 6 แบบใน [`prompts/`](prompts/) และรายการโจทย์ที่ค้างอยู่ใน
[`docs/open-questions.md`](docs/open-questions.md) — เรียงตามความสำคัญ P0–P3

## 🔎 ผลวิเคราะห์ที่มีอยู่แล้ว (530 ข้อ)

| ผลการประเมิน | จำนวน | ความหมาย |
|---|---|---|
| พอใช้ | 197 | ทำงานได้ แต่มีจุดควรปรับปรุง |
| เสี่ยง | 85 | ข้อมูลเสียหาย/ผิดเงิน/ความปลอดภัย/สูตรพังง่าย |
| ต้องปรับปรุง | 111 | มีข้อผิดพลาดเชิงตรรกะ/ข้อมูล/ประสิทธิภาพ |
| ต้องยืนยันในแอป | 120 | ต่างกันเฉพาะช่องว่าง — PDF ยืนยันไม่ได้ |
| ดี | 8 | ถูกต้อง ไม่มีจุดผิดพลาดที่กระทบธุรกิจ |
| ไม่มีสูตร | 9 | คอลัมน์ข้อมูลดิบ |

**สิ่งที่ยืนยันแล้วจาก PDF ต้นฉบับ 27 ข้อ** — เช่น

- `ปริ๊นใบวางบิล.ราคารวม` เขียน `Startdate`/`Enddate` แต่คอลัมน์จริงคือ `StartDate`/`EndDate` → สูตร error
- `แจ้งปัญหาระหว่างวัน` อ้าง `[Email พนักงาน]` และ `[DeliveryStatus]` ในขอบเขตที่ไม่มีคอลัมน์เหล่านี้เลย
- `Acknowledge_Logs.ข้อความประกาศ` — CONCATENATE มีสตริงติดกันไม่มีคั่น และมี comma ท้าย
- `ตารางงานประจำวัน.ลำดับแรก` — SELECT มี argument ว่าง

ดูทั้งหมดที่ [`analysis/reports/12-คุณภาพคอลัมน์และสูตร.md`](analysis/reports/12-คุณภาพคอลัมน์และสูตร.md)
และรายโดเมนที่ `analysis/reports/D01…D11-*.md`

### 6 ตารางที่ยังไม่มี Security filter
`ข้อมูลงานRT` · `ข้อมูลงานRW` · `FILTER` · `ข้อมูลชื่องานต้นทางปลายทาง` · `สรุป_Shipment` · `สรุป_เจ้าของสินค้า`
→ ทุกบทบาท (USER) เห็นและแก้ไขได้ทุกแถว **ควรแก้ก่อนเป็นอันดับแรก**

## 🔒 ข้อมูลส่วนบุคคล

ข้อมูลชุดนี้ถูก **ลบข้อมูลส่วนบุคคลแล้ว** ก่อนอัปโหลด:

| ชนิด | จำนวน | แทนด้วย |
|---|---|---|
| อีเมลพนักงาน | 14 | `employee01@example.invalid` |
| ชื่อพนักงาน (ในชื่อแอคชัน) | 16 | `person_01` |

CI จะ **ตรวจและ fail** ทุกครั้งที่พบอีเมลจริง (gmail/hotmail/outlook/…) เข้ามาใน repo
— เพราะพอมี AI มาช่วย มีโอกาสสูงที่จะมีคนวางอีเมลจริงลงไปเอง

**PDF ต้นฉบับ 1,946 หน้าไม่ได้อยู่ใน repo นี้** (ใหญ่ + มีข้อมูลส่วนบุคคล)
แต่ทุกอ็อบเจกต์มี `pdf_page` ของตัวเอง → ตรวจสอบย้อนกลับได้ถ้ามีสำเนา

## 🚀 การมีส่วนร่วม

- **AI agent** → อ่าน `AGENTS.md` → เลือกงานจาก `prompts/` หรือ `docs/open-questions.md`
  → เขียน `analysis/findings/<ชื่อ-agent>-<งาน>.json` → รัน `scripts/validate_findings.py` → เปิด PR
- **คน** → เปิด issue ด้วยฟอร์ม *AI finding* (เร็วกว่า) หรือ PR ที่มีไฟล์ใน `analysis/findings/`

ทุก PR จะผ่าน CI: ตรวจสัญญาข้อมูล · ตรวจคำศัพท์ · ตรวจว่าตารางที่อ้างมีจริง · **ตรวจว่าไม่มีข้อมูลส่วนบุคคล**
