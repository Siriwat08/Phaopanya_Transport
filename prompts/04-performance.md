# Task 04 — ประสิทธิภาพและความทนทานของสูตร

**เป้าหมาย:** หาสูตรที่จะช้าลงหรือพังเมื่อข้อมูลโตขึ้น และเสนอวิธีแก้ที่ไม่เปลี่ยนผลลัพธ์

## รูปแบบที่ต้องหา

| รูปแบบ | ทำไมถึงมีปัญหา | สิ่งที่ควรทำ |
|---|---|---|
| `SELECT` ซ้อนกันหลายชั้น | ทำงานซ้ำกับทุกแถวที่อ้างถึง | ย้ายเป็นคอลัมน์ช่วย 1 ชั้น |
| `COUNT(UNIQUE(SELECT(...)))` | หนักมากเมื่อแถวเพิ่ม | ใช้ `COUNTIF` / key column |
| `SORT(UNIQUE(LIST(...)))` | สร้าง list ใหม่ทุกครั้ง | คิดค่าครั้งเดียวเก็บไว้ |
| สูตรยาว > 400 ตัวอักษร | อ่านยาก แก้ยาก | แตกเป็นคอลัมน์ช่วย |
| ค่าคงที่ตัวเลขฝังในสูตร | เปลี่ยนกติกาแล้วลืมแก้ | ย้ายไปคอลัมน์ตั้งค่า |
| `Initial value` ที่ดึงข้อมูลตารางอื่น | คำนวณครั้งเดียวแล้วค้าง | ย้ายเป็น App formula |

## ขั้นที่ต้องทำ

1. ดึงความยาวสูตรและ nesting depth จาก `app/tables/*.json` → จัดอันดับ
2. หาสูตรที่อ้างถึงตารางที่มีข้อมูลเยอะ (ดูจำนวนแถวโดยประมาณจากจำนวนคอลัมน์ + จำนวนแอคชันที่เขียนลง)
3. สำหรับ 10 สูตรที่แย่ที่สุด เขียน "ก่อน/หลัง" เป็นตัวเลข และเสนอสูตรใหม่
4. ประเมินความเสี่ยงของการเปลี่ยน: ถ้าสูตรถูกใช้เป็นเงื่อนไขในหลายที่ → ต้องแก้ทุกจุด

## ผลลัพธ์ที่ต้องส่ง
