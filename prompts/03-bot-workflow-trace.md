# Task 03 — ไล่ logic บอททั้ง 30 ตัว

**เป้าหมาย:** ทำแผนที่ว่าบอทแต่ละตัวทำอะไร เรียกกันอย่างไร และจุดที่จะพัง

## โครงสร้าง

- บอท 30 ตัว → ตาราง `Process for … Process Table` 30 ตาราง + ตาราง `… Output` 30 ตาราง
- แอคชันชนิด `SET_COLUMN_VALUE` เป็นตัวเรียกบอท โดยตั้ง `ชื่องาน` + `ปริ๊นใบวางบิลแยกตามชื่องาน = TRUE`
- `ปริ๊นใบวางบิลทุกงาน` เป็น COMPOSITE 38 ขั้น

## ขั้นที่ต้องทำ

1. `app/actions.json` → หาแอคชันที่เป็นตัวเรียกบอท (ดู `With these properties` → `Assignments`)
2. สำหรับบอทแต่ละตัว เปิด `app/tables/process-for-*.json` → ดู Process Table ทำอะไร (คอลัมน์สถานะ) และ Output ที่เขียนออกมา
3. หาแอคชันที่อ้าง `ReferencedAction` → เชื่อมว่าบอทตัวไหนเรียกบอทตัวไหน
4. หาจุดที่ error แล้วธง `ปริ๊นใบวางบิลแยกตามชื่องาน` ค้างเป็น TRUE → บอทจะถูกเรียกซ้ำ

## ตารางที่ต้องส่ง

| บอท | ตาราง Process | ตาราง Output | เรียกจากแอคชัน | เขียนอะไร | จุดเสี่ยง |

พร้อมกับ:
- **แผนที่การไหลของข้อมูล** ระหว่างตารางจริง 30 ตาราง ↔ บอท 30 ตัว
- **รายการบอทที่ซ้ำซ้อน** (ทำงานกับข้อมูลชุดเดียวกัน)
- **จุดที่ควรมี idempotency**

## ข้อควรระวัง

- ตาราง Output เป็นตารางสถานะขั้นกลาง ไม่ใช่ข้อมูลธุรกิจ — อย่าสับสน
- `ReferencedRows` ของ REF_ACTION เป็นสูตรเลือกแถว → ตรวจขอบเขตตาม `docs/reading-the-pdf.md`
