# Task 05 — ความสมบูรณ์ข้ามตาราง (referential integrity)

**เป้าหมาย:** ตรวจว่าคอลัมน์ที่ชี้ไปตารางอื่น (Ref, key, lookup) ยังชี้ถูกอยู่ และไม่มีข้อมูลกำพร้า

## รูปแบบที่ต้องหา

1. **Ref column ที่ชี้ไปตารางที่หายไป** — `Type Qualifier.ReferencedTableName` เทียบกับรายชื่อตารางจริง
2. **คอลัมน์ที่ถูกอ้างถึงแต่ไม่มีในตารางเป้าหมาย** — เช่น `แจ้งปัญหาระหว่างวัน` อ้าง `[DeliveryStatus]` ที่ไม่มีในตารางนั้น
3. **ชื่อคอลัมน์ที่ต่างกันข้ามตาราง** — `Shipment No` ↔ `ShipmentNo`, `Plan Delivery` ↔ `PlanDelivery`, `Lat / Long` ↔ `Lat/Long`
4. **Key column ที่แก้ได้** — ทำให้การอ้างอิงพังได้
5. **LOOKUP ที่ค้นหาด้วยค่าที่ไม่ Unique** — เช่น ค้นด้วยชื่อลูกค้า (ชื่อซ้ำได้)

## ขั้นที่ต้องทำ

1. สร้างแผนที่ "ตาราง → คอลัมน์ที่อ้างถึงตารางอื่น" จาก `app/tables/*.json`
2. สำหรับทุกการอ้างอิง ใช้กฎขอบเขตใน `AGENTS.md` ข้อ 3.1 ตรวจว่าคอลัมน์เป้าหมายมีอยู่จริง
3. หาคู่ที่ "ต่างกันเฉพาะช่องว่าง" แล้วประเมินว่าควรยึดแบบไหน
4. เสนอแผนแก้ที่ปลอดภัย (เช่น เพิ่มคอลัมน์แชร์แทนการเปลี่ยนชื่อที่ใช้งานอยู่แล้ว)

## ผลลัพธ์ที่ต้องส่ง

| ตารางต้นทาง | คอลัมน์ | อ้างถึง | ตารางเป้าหมาย | สถานะ | ความเสี่ยง | วิธีแก้ |
