# Task 01 — Security audit

**เป้าหมาย:** ประเมินว่าใครเข้าถึงข้อมูลอะไรได้ และปิดช่องโหว่ที่ทำให้ข้อมูลส่วนบุคคล/ข้อมูลงานรั่ว

## ขั้นที่ต้องทำ

1. อ่าน `app/index.json` → เลือกตารางที่มีข้อมูลส่วนบุคคล (ชื่อพนักงาน อีเมล เบอร์โทร ทะเบียนรถ ที่อยู่ ลูกค้า)
2. เปิด `app/tables/<ตาราง>.json` → ดูคีย์ `Security filter` และ `Expression for update mode` ของ `table_record.props`
3. ตรวจว่าคอลัมน์ที่มีข้อมูลส่วนบุคคลได้ตั้ง `Sensitive data = Yes` หรือไม่
4. ตรวจว่ามีตารางที่ **ไม่มี** Security filter และ **ไม่มี** Expression for update mode พร้อมกัน
5. ตรวจว่าคอลัมน์ที่ถูกใช้เป็นเงื่อนไขใน Security filter แก้ไขได้หรือไม่ (Read-Only = No)

## สิ่งที่ต้องรายงาน (สำหรับแต่ละตาราง)

| ประเด็น | ต้องตอบ |
|---|---|
| ตาราง | ชื่อตาราง |
| ใครเห็นข้อมูล | ทุกบทบาท / เฉพาะ ADMIN / ผู้ที่เป็นเจ้าของแถว / ผู้อนุมัติ |
| แก้ไขได้ไหม | ทุกคน / เจ้าของแถว / ไม่ได้ |
| ข้อมูลส่วนบุคคลที่รั่ว | คอลัมน์ไหนบ้าง |
| ระดับความเสี่ยง | critical / high / medium / low |
| สูตร Security filter ที่ควรเป็น | สูตรจริงที่เสนอ |

## ข้อควรระวัง

- เกณฑ์ความเสี่ยงของแอปนี้: โปรแกรม `USER` = พนักงานขับรถ / ผู้รับงาน · `ADMIN` = ฝ่ายกลาง
- ตารางที่เป็น "ตารางสรุป" (สรุป_Shipment, สรุป_เจ้าของสินค้า) อาจตั้งใจให้ทุกคนเห็น — ให้เสนอทางเลือก ไม่ใช่ประกาศว่าผิด
- ห้ามเสนอให้ลบข้อมูล ให้เสนอการจำกัดการเข้าถึง
