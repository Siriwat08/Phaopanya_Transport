### 📖 คำศัพท์ที่จะเจอในไฟล์นี้ (แปลเป็นภาษาธรรมดา)

| คำเทคนิค | แปลง่าย ๆ ว่า |
|---|---|
| สูตร (Formula) | โจทย์คณิตที่พิมพ์ไว้ล่วงหน้าให้แอปคำนวณเอง เหมือนตั้งโจทย์ไว้ในเครื่องคิดเลข |
| App formula | สูตรแบบ "ล็อกถาวร" — แอปคิดค่าเดียวตลอด คนพิมพ์ทับไม่ได้ (เหมือนตราประทับ) |
| Initial value | ค่าเริ่มต้นที่แอปเติมให้ก่อน แต่คนใช้ยังเปลี่ยนได้ |
| Valid_If | "ยามเฝ้าประตู" ตรวจค่าก่อนบันทึก — ไม่ผ่าน = บันทึกไม่ได้ |
| Show_If | "ม่าน" ที่เปิดเฉพาะสถานการณ์ที่กำหนด — ไม่เข้าเงื่อนไข ช่องนั้นจะซ่อน |
| Editable_If | กุญแจที่แจกเฉพาะบางคน — คนอื่นแก้ช่องนี้ไม่ได้ |
| Read-Only | ช่องที่ "ดูได้ พิมพ์ไม่ได้" |
| Ref / อ้างอิง | สายเชื่อมไปดึงข้อมูลจากแฟ้มอื่น เหมือนสายโทรศัพท์ระหว่างห้อง |
| Key | หมายเลขบัตรประชาชนของแต่ละแถว — ห้ามซ้ำ ห้ามแก้ |
| Virtual column | ช่องคำนวณสด ไม่เก็บลง Google Sheet — เหมือนจอ LED ไม่ใช่กระดาษ |
| Security filter | ฉากกั้นข้อมูล ให้แต่ละคนเห็นเฉพาะงานของตัวเอง |

**สัญลักษณ์สีที่ใช้ทั้งชุดคู่มือ:** 🔴 = ต้องรีบดู (เสี่ยงเงิน/ข้อมูลพัง) · 🟠 = ควรแก้ (ผิดตรรกะ) · 🟡 = ทำงานได้แต่ควรปรับ · ❓ = ต้องกดลองในแอปจริงเท่านั้นถึงจะรู้ · ✅ = ปกติ/ดีอยู่แล้ว · ⚪ = ช่องข้อมูลดิบ ไม่มีสูตร

## 🗺️ ทางเข้าแก้ไขใน AppSheet Editor (อ่านก่อนเริ่ม — สำหรับมือใหม่)

1. เปิดเบราว์เซอร์ไปที่ https://www.appsheet.com แล้วเข้าสู่ระบบด้วยบัญชีเจ้าของแอป
2. คลิก **My apps** → เลือกแอป **เผ่าปัญญาทรานสปอร์ต** → คลิกเมนู ⋮ → **Edit** (เข้าสู่ AppSheet Editor)
3. คลิกแท็บ **Data** ที่แถบซ้าย → กลุ่ม **Tables** → คลิกตาราง **สรุป_เจ้าของสินค้า**
4. จะเห็นรายการคอลัมน์ทั้งหมด → คลิก **ไอคอนดินสอ (pencil)** หน้าคอลัมน์ที่ต้องการแก้
5. แก้ค่าตามคู่มือด้านล่าง → กด **Done** → กด **Save** ที่แถบบนขวาของ Editor (สำคัญ! ถ้าไม่ Save การแก้จะไม่ถูกบันทึก)
6. 💡 เคล็ดลับ: ก่อนแก้จริง ให้กด **⋮ ▸ Version history** ใน Google Sheet เพื่อย้อนกลับได้ และควรสำรองสูตรเดิมด้วยการคัดลอกไปไว้ในไฟล์ Notepad ก่อน

**คำเตือนก่อนแก้:**

- แก้ทีละจุด แล้วทดสอบในแอปจริงทุกครั้ง (เปิดแอปบนมือถือ/เว็บ กด Sync แล้วลองกรอกงานจริง 1 เคส)
- AppSheet แยกชื่อคอลัมน์แบบตัวพิมพ์ใหญ่-เล็ก และแยกวรรค: `StartDate` ≠ `Startdate`, `ชื่องาน` ≠ `ชื่อ งาน`
- `[X]` ใน `SELECT(ตารางอื่น[...])` คือคอลัมน์ของ "ตารางอื่น" ไม่ใช่ของตารางที่สูตรอยู่ — อย่าเผลอไปแก้ชื่อที่จริงไม่ผิด

## 🚨 ปัญหาระดับตาราง (แก้ก่อนรายคอลัมน์)

### 🚨 ปัญหา 1: 🟠 [MEDIUM] ตารางไม่มี Security filter → ผู้ใช้ทุกบทบาทเห็นข้อมูลทุกแถว

- **ทำไมสำคัญ:** Security filter คือด่านตัดข้อมูลที่ฝั่งเซิร์ฟเวอร์ ถ้าไม่มี ทุกแถวถูกดาวน์โหลดลงเครื่องทุกผู้ใช้ แม้หน้าจอซ่อนไว้ก็หลุดผ่านวิวอื่นได้
- **วิธีแก้ทีละขั้น (จุดแก้:** `Data ▸ Tables ▸ คลิกตารางนี้ ▸ ช่อง "Security filter"`):**
   1. คลิกช่อง "Security filter" (ถ้าไม่มีช่องนี้ คลิก + สร้างในกลุ่ม Table settings หรือแก้ผ่าน "Table properties")
   2. วางสูตรด้านล่าง — ปรับ [Email พนักงาน] เป็นชื่อคอลัมน์อีเมลของตารางนี้ให้ตรง
   3. กด Save — ทดสอบด้วยบัญชี USER ว่าเห็นเฉพาะแถวของตัวเอง

**สูตรที่ใช้ (คัดลอกไปวางได้):**

```
=OR(USERROLE() = "ADMIN", [Email พนักงาน] = USEREMAIL())
```

- **ตรวจว่าแก้สำเร็จ:** ล็อกอินด้วย USER แล้วตรวจว่าเห็นเฉพาะแถวของตัวเอง

### 🚨 ปัญหา 2: 🟠 [MEDIUM] ไม่มี Expression for update mode → ค่าเริ่มต้น ALL_CHANGES ผู้ใช้ทุกคนแก้/ลบได้

- **ทำไมสำคัญ:** การลบแถวใน no-code ย้อนกลับยาก ควรจำกัดสิทธิ์ลบให้ ADMIN
- **วิธีแก้ทีละขั้น (จุดแก้:** `Data ▸ Tables ▸ คลิกตารางนี้ ▸ ช่อง "Expression for update mode"`):**
   1. คลิกช่อง "Expression for update mode"
   2. วางสูตรด้านล่าง (USER จะเพิ่ม/แก้ได้ แต่ลบไม่ได้)
   3. Save แล้วทดสอบลบแถวด้วยบัญชี USER ต้องถูกบล็อก

**สูตรที่ใช้ (คัดลอกไปวางได้):**

```
=SWITCH(USERROLE(), "ADMIN", "ALL_CHANGES", "USER", "ADDS_AND_UPDATES", "READ_ONLY")
```

- **ตรวจว่าแก้สำเร็จ:** ลองลบแถวด้วย USER ธรรมดา ต้องลบไม่ได้

### 🚨 ข้อค้นพบ 3 (วิเคราะห์พื้นฐาน) [ต้องปรับปรุง] ตารางนี้ไม่มี Security filter ทำให้ผู้ใช้ทุกบทบาท (USER) เห็นข้อมูลทั้งหมด

- **ผลต่องาน:** ข้อมูลข้ามผู้ใช้หลุดรั่ว — ทั้งข้อมูลงานและข้อมูลลูกค้า
- **วิธีแก้:** ตั้ง Security filter ให้เหมือนตารางหลักของแอป

**สูตรแนะนำ:**

```
=OR(USERROLE() = "ADMIN", [Email พนักงาน] = USEREMAIL())
```

### 🚨 ข้อค้นพบ 4 (วิเคราะห์พื้นฐาน) [ต้องปรับปรุง] ไม่มี Expression for update mode → ค่าเริ่มต้น ALL_CHANGES ทำให้ผู้ใช้ทุกคนแก้/ลบข้อมูลได้

- **ผลต่องาน:** ผู้ใช้ทั่วไปแก้ไขหรือลบแถวได้ โดยไม่ได้รับการควบคุม
- **วิธีแก้:** เพิ่ม Expression for update mode ให้ USER เป็น READ_ONLY หรือ ADDS_AND_UPDATES

**สูตรแนะนำ:**

```
=SWITCH(USERROLE(), "ADMIN", "ALL_CHANGES", "USER", "READ_ONLY", "READ_ONLY")
```

#### ปัญหา 1: [🔴 ระดับ high] คอลัมน์ Key ปล่อยให้แก้ไขได้ (Read-Only = No)

- **ทำไมสำคัญ:** Key คือตัวตนของแถว — แก้แล้วระบบมองเป็นแถวใหม่ ข้อมูลเดิมกลายเป็นแถวค้าง สูตร REF พังทันที
- **วิธีแก้ทีละขั้น (จุดแก้:** `Data ▸ Tables ▸ คลิกตารางนี้ ▸ คลิกไอคอนดินสอ ที่คอลัมน์ Key นี้`):**
   1. สลับ "Read-Only?" เป็น Yes และ "Hidden?" เป็น Yes
   2. เพิ่ม Initial value: UNIQUEID() ตามสูตรด้านล่าง (สำหรับแถวใหม่)
   3. Save แล้วทดสอบสร้างแถวใหม่ คีย์ต้องถูกสร้างอัตโนมัติ

**สูตร/ค่าที่ใช้ (คัดลอกไปวางได้):**

```
=UNIQUEID()
```

- **ตรวจว่าแก้สำเร็จ:** ลองแก้คีย์ในแอป ต้องแก้ไม่ได้

#### ข้อค้นพบ 2 (จากการวิเคราะห์พื้นฐาน): 🟡 [พอใช้] คอลัมน์ Key ไม่ได้ล็อกการแก้ไข → ผู้ใช้แก้หรือคัดลอก Key ได้ ทำให้ข้อมูลอ้างอิงผิด

- **หลักฐาน:** Key = Yes, Read-Only = No
- **ผลต่องาน:** ความสัมพันธ์ระหว่างตารางเสียหาย
- **วิธีแก้:** ตั้ง Read-Only = Yes สำหรับคอลัมน์ Key

- **วิธีตรวจ:** เปิดคอลัมน์ `SummaryKey` ของตาราง `สรุป_เจ้าของสินค้า` ในแอป แล้วตรวจว่าปัญหาที่อธิบายไว้ ยังเกิดอยู่จริงหรือไม่
