เป็น **สมุดบันทึกการวางบิลกับลูกค้า** — รวบยอดงานส่งเป็นเอกสารบิลเดียว เป็นแฟ้มที่มีตัวเลขเงินเยอะที่สุดจึงเจอจุดเสี่ยงมากที่สุดด้วย (9 จุด 🔴) เหมือนห้องคลังเงินของตึก

### 📖 คำศัพท์ที่จะเจอในไฟล์นี้ (แปลเป็นภาษาธรรมดา)

| คำเทคนิค | แปลง่าย ๆ ว่า |
|---|---|
| สูตร (Formula) | โจทย์คณิตที่พิมพ์ไว้ล่วงหน้าให้แอปคำนวณเอง เหมือนตั้งโจทย์ไว้ในเครื่องคิดเลข |
| App formula | สูตรแบบ "ล็อกถาวร" — แอปคิดค่าเดียวตลอด คนพิมพ์ทับไม่ได้ (เหมือนตราประทับ) |
| Initial value | ค่าเริ่มต้นที่แอปเติมให้ก่อน แต่คนใช้ยังเปลี่ยนได้ |
| Valid_If | "ยามเฝ้าประตู" ตรวจค่าก่อนบันทึก — ไม่ผ่าน = บันทึกไม่ได้ |
| Show_If | "ม่าน" ที่เปิดเฉพาะสถานการณ์ที่กำหนด — ไม่เข้าเงื่อนไข ช่องนั้นจะซ่อน |
| Editable_If | กุญแจที่แจกเฉพาะบางคน — คนอื่นแก้ช่องนี้ไม่ได้ |
| Read-Only | ช่องที่ "ดูได้ พิมพ์ไม่ได้" |
| Ref / อ้างอิง | สายเชื่อมไปดึงข้อมูลจากแฟ้มอื่น เหมือนสายโทรศัพท์ระหว่างห้อง |
| Key | หมายเลขบัตรประชาชนของแต่ละแถว — ห้ามซ้ำ ห้ามแก้ |
| Virtual column | ช่องคำนวณสด ไม่เก็บลง Google Sheet — เหมือนจอ LED ไม่ใช่กระดาษ |
| Security filter | ฉากกั้นข้อมูล ให้แต่ละคนเห็นเฉพาะงานของตัวเอง |

**สัญลักษณ์สีที่ใช้ทั้งชุดคู่มือ:** 🔴 = ต้องรีบดู (เสี่ยงเงิน/ข้อมูลพัง) · 🟠 = ควรแก้ (ผิดตรรกะ) · 🟡 = ทำงานได้แต่ควรปรับ · ❓ = ต้องกดลองในแอปจริงเท่านั้นถึงจะรู้ · ✅ = ปกติ/ดีอยู่แล้ว · ⚪ = ช่องข้อมูลดิบ ไม่มีสูตร

## 🗺️ ทางเข้าแก้ไขใน AppSheet Editor (อ่านก่อนเริ่ม — สำหรับมือใหม่)

1. เปิดเบราว์เซอร์ไปที่ https://www.appsheet.com แล้วเข้าสู่ระบบด้วยบัญชีเจ้าของแอป
2. คลิก **My apps** → เลือกแอป **เผ่าปัญญาทรานสปอร์ต** → คลิกเมนู ⋮ → **Edit** (เข้าสู่ AppSheet Editor)
3. คลิกแท็บ **Data** ที่แถบซ้าย → กลุ่ม **Tables** → คลิกตาราง **ข้อมูลการวางบิล**
4. จะเห็นรายการคอลัมน์ทั้งหมด → คลิก **ไอคอนดินสอ (pencil)** หน้าคอลัมน์ที่ต้องการแก้
5. แก้ค่าตามคู่มือด้านล่าง → กด **Done** → กด **Save** ที่แถบบนขวาของ Editor (สำคัญ! ถ้าไม่ Save การแก้จะไม่ถูกบันทึก)
6. 💡 เคล็ดลับ: ก่อนแก้จริง ให้กด **⋮ ▸ Version history** ใน Google Sheet เพื่อย้อนกลับได้ และควรสำรองสูตรเดิมด้วยการคัดลอกไปไว้ในไฟล์ Notepad ก่อน

**คำเตือนก่อนแก้:**

- แก้ทีละจุด แล้วทดสอบในแอปจริงทุกครั้ง (เปิดแอปบนมือถือ/เว็บ กด Sync แล้วลองกรอกงานจริง 1 เคส)
- AppSheet แยกชื่อคอลัมน์แบบตัวพิมพ์ใหญ่-เล็ก และแยกวรรค: `StartDate` ≠ `Startdate`, `ชื่องาน` ≠ `ชื่อ งาน`
- `[X]` ใน `SELECT(ตารางอื่น[...])` คือคอลัมน์ของ "ตารางอื่น" ไม่ใช่ของตารางที่สูตรอยู่ — อย่าเผลอไปแก้ชื่อที่จริงไม่ผิด

**สถานะ: 🟠 ต้องปรับปรุง** — พบปัญหา 4 ข้อ

#### ปัญหา 1: [🟠 ระดับ medium] คอลัมน์นี้เก็บรหัสพนักงาน (PII) แต่ยังไม่ได้ตั้ง Sensitive data = Yes

- **ทำไมสำคัญ:** การตั้ง Sensitive data ทำให้แอปจัดการข้อมูลส่วนบุคคลถูกหลัก PDPA — ค่าจะถูกซ่อนจากบันทึกการแชร์และการส่งออกโดยไม่ตั้งใจ
- **วิธีแก้ทีละขั้น (จุดแก้:** `Data ▸ Tables ▸ คลิกตารางนี้ ▸ คลิกไอคอนดินสอ (pencil) ที่คอลัมน์นี้`):**
   1. ในหน้าตั้งค่าคอลัมน์ มองหากลุ่ม "Column properties"
   2. สลับสวิตช์ "Sensitive data?" จาก No เป็น Yes
   3. กด "Save" ด้านบนขวา แล้วกด Save อีกครั้งที่แถบด้านบนของ Editor

- **ตรวจว่าแก้สำเร็จ:** เปิด Data > Columns > คอลัมน์นี้ ตรวจว่าช่อง Sensitive data เป็น Yes

#### ข้อค้นพบ 2 (จากการวิเคราะห์พื้นฐาน): 🟠 [ต้องปรับปรุง] ค่านี้คำนวณจากข้อมูลของตารางอื่น/แถวอื่น แต่ถูกตั้งเป็น Initial value — จึงถูกคำนวณรอบครั้งตอนสร้างแถว แล้วค้างค่าเดิมตลอดไป

- **หลักฐาน:** Initial value = =LOOKUP(USEREMAIL(), "ข้อมูลพนักงาน", "Email พนักงาน", "ID_พนักงาน") (ไม่มี App formula)
- **ผลต่องาน:** เมื่อข้อมูลต้นทางเปลี่ยน (สถานะงาน, ราคา, ผู้รับ) ค่านี้จะไม่อัปเดต → ข้อมูลเก่าค้าง
- **วิธีแก้:** ย้ายเป็น App formula (หรือเติม Editable initial value) ให้คำนวณใหม่ทุกครั้ง

**สูตรแนะนำ (คัดลอกไปวางได้ — ปรับชื่อคอลัมน์ให้ตรงแอปจริงก่อนใช้):**

```
=LOOKUP(USEREMAIL(), "ข้อมูลพนักงาน", "Email พนักงาน", "ID_พนักงาน")
```

- **วิธีตรวจ:** เปิดคอลัมน์ `ID_พนักงาน` ของตาราง `ข้อมูลการวางบิล` ในแอป แล้วตรวจว่าปัญหาที่อธิบายไว้ ยังเกิดอยู่จริงหรือไม่

#### ข้อค้นพบ 3 (จากการวิเคราะห์พื้นฐาน): 🟡 [พอใช้] คอลัมน์เป็นข้อมูลส่วนบุคคลแต่ไม่ได้ทำเครื่องหมาย Sensitive data = Yes

- **หลักฐาน:** Sensitive data = No
- **ผลต่องาน:** ผู้ที่เห็นตารางนี้จะเห็นข้อมูลส่วนบุคคลในไฟล์ export และในแอป
- **วิธีแก้:** ตั้ง Sensitive data = Yes

- **วิธีตรวจ:** เปิดคอลัมน์ `ID_พนักงาน` ของตาราง `ข้อมูลการวางบิล` ในแอป แล้วตรวจว่าปัญหาที่อธิบายไว้ ยังเกิดอยู่จริงหรือไม่

#### ข้อค้นพบ 4 (จากการวิเคราะห์พื้นฐาน): 🟡 [พอใช้] ใช้ LOOKUP หา ID_พนักงาน จากอีเมล ถ้าอีเมลนี้ไม่มีในตาราง 'ข้อมูลพนักงาน' จะได้ค่าว่างโดยไม่มีสัญญาณเตือน และไม่มีการตรวจว่าอีเมลซ้ำ/เป็นผู้ใช้ที่เลิกใช้งานแล้ว

- **หลักฐาน:** สูตร =LOOKUP(USEREMAIL(), "ข้อมูลพนักงาน", "Email พนักงาน","ID_พนักงาน") (ไม่มี IFERROR/ISBLANK)
- **ผลต่องาน:** แถวที่สร้างโดยคนที่ไม่มีในตารางพนักงานจะไม่มีชื่อ-นามสกุล/ทะเบียนรถ ทำให้แยกยอดรายคน (ราคารวมคนขับใน T4) ไม่ได้ และคอลัมน์ 'ชื่อ - นามสกุล' ว่างทำให้รายงานรายคนขับหายไปเงียบ ๆ
- **วิธีแก้:** เพิ่มเงื่อนไขบังคับ: =IF(ISBLANK(LOOKUP(USEREMAIL(), "ข้อมูลพนักงาน", "Email พนักงาน","ID_พนักงาน")), NA(), LOOKUP(USEREMAIL(), "ข้อมูลพนักงาน", "Email พนักงาน","ID_พนักงาน")) และตั้ง Required_If = NOT(ISBLANK(USEREMAIL())) ในตาราง 'ข้อมูลพนักงาน' ให้อีเมลไม่ซ้ำ

**สูตรแนะนำ (คัดลอกไปวางได้ — ปรับชื่อคอลัมน์ให้ตรงแอปจริงก่อนใช้):**

```
=IF(ISBLANK(LOOKUP(USEREMAIL(), "ข้อมูลพนักงาน", "Email พนักงาน","ID_พนักงาน")), NA(), LOOKUP(USEREMAIL(), "ข้อมูลพนักงาน", "Email พนักงาน","ID_พนักงาน"))
```

- **วิธีตรวจ:** เปิดคอลัมน์ `ID_พนักงาน` ของตาราง `ข้อมูลการวางบิล` ในแอป แล้วตรวจว่าปัญหาที่อธิบายไว้ ยังเกิดอยู่จริงหรือไม่

   1. คลิกช่อง "App formula" แล้วคัดลอกสูตรจากช่อง "Initial value" ไปวาง
   2. ลบสูตรออกจากช่อง "Initial value" (เลือกข้อความแล้ว Delete)
   3. กด "Done" แล้ว Save — เปิดแอปทดสอบแก้ข้อมูลต้นทาง ค่าต้องเปลี่ยนตามเมื่อ Sync

```

```

- **ตรวจว่าแก้สำเร็จ:** แก้ข้อมูลต้นทางแล้วคอลัมน์นี้ต้องเปลี่ยนตามเมื่อ sync

#### ปัญหา 1: [🟠 ระดับ medium] คอลัมน์นี้เก็บอีเมล (PII) แต่ยังไม่ได้ตั้ง Sensitive data = Yes

- **ทำไมสำคัญ:** การตั้ง Sensitive data ทำให้แอปจัดการข้อมูลส่วนบุคคลถูกหลัก PDPA — ค่าจะถูกซ่อนจากบันทึกการแชร์และการส่งออกโดยไม่ตั้งใจ

   1. ในหน้าตั้งค่าคอลัมน์ มองหากลุ่ม "Column properties"
   2. สลับสวิตช์ "Sensitive data?" จาก No เป็น Yes
   3. กด "Save" ด้านบนขวา แล้วกด Save อีกครั้งที่แถบด้านบนของ Editor

- **ตรวจว่าแก้สำเร็จ:** เปิด Data > Columns > คอลัมน์นี้ ตรวจว่าช่อง Sensitive data เป็น Yes

#### ปัญหา 2: [🔴 ระดับ high] คอลัมน์อีเมลถูกใช้เป็น Security filter ของตาราง แต่ Read-Only = No ผู้ใช้แก้ค่าได้

- **ทำไมสำคัญ:** แก้อีเมลในแถวตัวเองแล้วขอบเขตข้อมูลที่เห็นเปลี่ยนทันที — เปิดช่องให้ขยับข้อมูลข้ามผู้ใช้โดยไม่ตั้งใจ
- **วิธีแก้ทีละขั้น (จุดแก้:** `Data ▸ Tables ▸ คลิกตารางนี้ ▸ คลิกไอคอนดินสอ ที่คอลัมน์อีเมลนี้`):**
   1. ในหน้าตั้งค่าคอลัมน์ เลื่อนไปกลุ่ม "Type Details"
   2. คลิกช่อง "Editable_If" (หรือ Data validity ▸ Editable_If ตามเวอร์ชัน Editor)


#### ข้อค้นพบ 5 (จากการวิเคราะห์พื้นฐาน): 🚨 [เสี่ยง] (1) ใช้ ANY(SELECT(ราคาน้ำมันดีเซล[ราคา/หน่วย], ...)) ดึง 'ราคา/หน่วย' 3 จุด (คืน Boolean ไม่ใช่ตัวเลข) ; (2) เงื่อนไขสาขา override ตรวจแค่ว่า 'มีแถว PriceOverride ที่ช่วงวันที่ทับกัน' ไม่ได้ตรวจว่ามีราคาน้ำมันจริงในวันที่ UsePriceDate หรือไม่ → ถ้าไม่มี เรทจะเป็นค่าว่าง/0 และจะไม่ fallback ไปใช้ราคาวันที่ 25 ของเดือนก่อน ; (3) fallback ฝังกฎ 'ใช้ราคาวันที่ 25 ของเดือนก่อน' ไว้ในสูตร ถ้าตารางราคาน้ำมันอัปเดตเป็นวันที่ 1 ของเดือน จะไม่มีราคา → เรท 0 → ไม่เข้าแถบราคาใน Price_Table → ราคาตามระยะทาง 0 ; (4) ช่วงวันที่ที่ทับกันใน PriceOverride ไม่มีกฎเลือกแถว (ได้แถวแรกตามลำดับ) ; (5) สูตรยาว ~900 ตัวอักษร ซ้อน IF 4 ชั้น ฝัง DATE/CONCATENATE/EOMONTH — แก้ยากและช้า

- **วิธีแก้:** 1) ทดสอบ ANY(SELECT(...)) บนแถวตัวอย่างแล้วเปลี่ยนเป็น INDEX(SELECT(...),1) 2) แยกเป็นคอลัมน์ช่วย 3 ตัว: 'วันที่เรทที่ใช้' (เลือกวันที่จาก override/fallback ตามลำดับความสำคัญ), 'เรทดีเซล (จากตารางราคา)', 'แหล่งที่มาของเรท' แล้วใช้ LOOKUP ดึงราคา 3) แทนกฎวันที่ 25 ด้วยคอลัมน์ 'วันที่อ้างอิงราคา' ในตาราง ราคาน้ำมันดีเซล (หรือใช้ LOOKUP แบบ 'วันที่ล่าสุดที่ <= วันที่อ้างอิง') 4) เพิ่ม Valid_If ใน PriceOverride ว่า UsePriceDate ต้องมีอยู่จริงใน ราคาน้ำมันดีเซล
