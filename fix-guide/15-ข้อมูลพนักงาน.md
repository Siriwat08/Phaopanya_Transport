> โดเมน D07 — พนักงานและข้อมูลบุคคล (Staff Master Data) · ไฟล์สเปก `app/tables/main/15.json`

## 📌 ภาพรวมตารางนี้

- **คอลัมน์ทั้งหมด:** 17 ตัว · **Actions:** 7 รายการ
- **ผลตรวจรายคอลัมน์:** 🔴 เสี่ยง 1 · 🟠 ต้องปรับปรุง 0 · 🟡 พอใช้ 4 · ❓ ต้องยืนยันในแอป 0 · ✅ ปกติ 12
- **Security filter ปัจจุบัน:** `ไม่มี ⚠️`
- **Update mode:** ALL_CHANGES (มี expression: `=SWITCH(USERROLE(), "ADMIN", "ALL_CHANGES", "USER","READ_ONLY", "READ_ONLY")`)
- **Key ของตาราง:** ID_พนักงาน
- **ถูกอ้างอิงจากตาราง (Ref เข้า):** SCGนครหลวงJWDภูมิภาค, ข้อมูลการวางบิล, ข้อมูลการเข้าบำรุงรักษา, ทำเบิกส่วนต่างScgวังน้อย, รับงานคืนได้เงิน200, ส่งงานที่ยังไม่มีข้อมูลในระบบ, แจ้งปัญหาระหว่างวัน

## 🗺️ ทางเข้าแก้ไขใน AppSheet Editor (อ่านก่อนเริ่ม — สำหรับมือใหม่)

1. เปิดเบราว์เซอร์ไปที่ https://www.appsheet.com แล้วเข้าสู่ระบบด้วยบัญชีเจ้าของแอป
2. คลิก **My apps** → เลือกแอป **เผ่าปัญญาทรานสปอร์ต** → คลิกเมนู ⋮ → **Edit** (เข้าสู่ AppSheet Editor)
3. คลิกแท็บ **Data** ที่แถบซ้าย → กลุ่ม **Tables** → คลิกตาราง **ข้อมูลพนักงาน**
4. จะเห็นรายการคอลัมน์ทั้งหมด → คลิก **ไอคอนดินสอ (pencil)** หน้าคอลัมน์ที่ต้องการแก้
5. แก้ค่าตามคู่มือด้านล่าง → กด **Done** → กด **Save** ที่แถบบนขวาของ Editor (สำคัญ! ถ้าไม่ Save การแก้จะไม่ถูกบันทึก)
6. 💡 เคล็ดลับ: ก่อนแก้จริง ให้กด **⋮ ▸ Version history** ใน Google Sheet เพื่อย้อนกลับได้ และควรสำรองสูตรเดิมด้วยการคัดลอกไปไว้ในไฟล์ Notepad ก่อน

**คำเตือนก่อนแก้:**

- แก้ทีละจุด แล้วทดสอบในแอปจริงทุกครั้ง (เปิดแอปบนมือถือ/เว็บ กด Sync แล้วลองกรอกงานจริง 1 เคส)
- AppSheet แยกชื่อคอลัมน์แบบตัวพิมพ์ใหญ่-เล็ก และแยกวรรค: `StartDate` ≠ `Startdate`, `ชื่องาน` ≠ `ชื่อ งาน`
- `[X]` ใน `SELECT(ตารางอื่น[...])` คือคอลัมน์ของ "ตารางอื่น" ไม่ใช่ของตารางที่สูตรอยู่ — อย่าเผลอไปแก้ชื่อที่จริงไม่ผิด

## 🚨 ปัญหาระดับตาราง (แก้ก่อนรายคอลัมน์)

### 🚨 ปัญหา 1: 🔴 [HIGH] ตารางไม่มี Security filter → ผู้ใช้ทุกบทบาทเห็นข้อมูลทุกแถว รวมข้อมูลส่วนบุคคล: ID_พนักงาน, ชื่อ - นามสกุล, เบอร์โทรศัพท์, ทะเบียนรถ, Email พนักงาน

- **ทำไมสำคัญ:** Security filter คือด่านตัดข้อมูลที่ฝั่งเซิร์ฟเวอร์ ถ้าไม่มี ทุกแถวถูกดาวน์โหลดลงเครื่องทุกผู้ใช้ แม้หน้าจอซ่อนไว้ก็หลุดผ่านวิวอื่นได้
- **วิธีแก้ทีละขั้น (จุดแก้:** `Data ▸ Tables ▸ คลิกตารางนี้ ▸ ช่อง "Security filter"`):**
   1. คลิกช่อง "Security filter" (ถ้าไม่มีช่องนี้ คลิก + สร้างในกลุ่ม Table settings หรือแก้ผ่าน "Table properties")
   2. วางสูตรด้านล่าง — ปรับ [Email พนักงาน] เป็นชื่อคอลัมน์อีเมลของตารางนี้ให้ตรง
   3. กด Save — ทดสอบด้วยบัญชี USER ว่าเห็นเฉพาะแถวของตัวเอง

**สูตรที่ใช้ (คัดลอกไปวางได้):**

```
=OR(USERROLE() = "ADMIN", [Email พนักงาน] = USEREMAIL())
```

- **ตรวจว่าแก้สำเร็จ:** ล็อกอินด้วย USER แล้วตรวจว่าเห็นเฉพาะแถวของตัวเอง

### 🚨 ข้อค้นพบ 2 (วิเคราะห์พื้นฐาน) [เสี่ยง] ตารางนี้ไม่มี Security filter ทำให้ผู้ใช้ทุกบทบาท (USER) เห็นข้อมูลทั้งหมด รวมถึงข้อมูลส่วนบุคคล (ID_พนักงาน, ชื่อ - นามสกุล, เบอร์โทรศัพท์, ทะเบียนรถ)

- **ผลต่องาน:** ข้อมูลข้ามผู้ใช้หลุดรั่ว — ทั้งข้อมูลงานและข้อมูลลูกค้า
- **วิธีแก้:** ตั้ง Security filter ให้เหมือนตารางหลักของแอป

**สูตรแนะนำ:**

```
=OR(USERROLE() = "ADMIN", [Email พนักงาน] = USEREMAIL())
```

**สถานะ: 🔴 เสี่ยง** — พบปัญหา 4 ข้อ

#### ปัญหา 1: [🟠 ระดับ medium] คอลัมน์นี้เก็บรหัสพนักงาน (PII) แต่ยังไม่ได้ตั้ง Sensitive data = Yes

- **ทำไมสำคัญ:** การตั้ง Sensitive data ทำให้แอปจัดการข้อมูลส่วนบุคคลถูกหลัก PDPA — ค่าจะถูกซ่อนจากบันทึกการแชร์และการส่งออกโดยไม่ตั้งใจ
- **วิธีแก้ทีละขั้น (จุดแก้:** `Data ▸ Tables ▸ คลิกตารางนี้ ▸ คลิกไอคอนดินสอ (pencil) ที่คอลัมน์นี้`):**
   1. ในหน้าตั้งค่าคอลัมน์ มองหากลุ่ม "Column properties"
   2. สลับสวิตช์ "Sensitive data?" จาก No เป็น Yes
   3. กด "Save" ด้านบนขวา แล้วกด Save อีกครั้งที่แถบด้านบนของ Editor

- **ตรวจว่าแก้สำเร็จ:** เปิด Data > Columns > คอลัมน์นี้ ตรวจว่าช่อง Sensitive data เป็น Yes

#### ปัญหา 2: [🔴 ระดับ high] คอลัมน์ Key ปล่อยให้แก้ไขได้ (Read-Only = No)

- **ทำไมสำคัญ:** Key คือตัวตนของแถว — แก้แล้วระบบมองเป็นแถวใหม่ ข้อมูลเดิมกลายเป็นแถวค้าง สูตร REF พังทันที
- **วิธีแก้ทีละขั้น (จุดแก้:** `Data ▸ Tables ▸ คลิกตารางนี้ ▸ คลิกไอคอนดินสอ ที่คอลัมน์ Key นี้`):**
   1. สลับ "Read-Only?" เป็น Yes และ "Hidden?" เป็น Yes
   2. เพิ่ม Initial value: UNIQUEID() ตามสูตรด้านล่าง (สำหรับแถวใหม่)
   3. Save แล้วทดสอบสร้างแถวใหม่ คีย์ต้องถูกสร้างอัตโนมัติ

**สูตร/ค่าที่ใช้ (คัดลอกไปวางได้):**

```
=UNIQUEID()
```

- **ตรวจว่าแก้สำเร็จ:** ลองแก้คีย์ในแอป ต้องแก้ไม่ได้

#### ข้อค้นพบ 3 (จากการวิเคราะห์พื้นฐาน): 🟡 [พอใช้] คอลัมน์เป็นข้อมูลส่วนบุคคลแต่ไม่ได้ทำเครื่องหมาย Sensitive data = Yes

- **หลักฐาน:** Sensitive data = No
- **ผลต่องาน:** ผู้ที่เห็นตารางนี้จะเห็นข้อมูลส่วนบุคคลในไฟล์ export และในแอป
- **วิธีแก้:** ตั้ง Sensitive data = Yes

- **วิธีตรวจ:** เปิดคอลัมน์ `ID_พนักงาน` ของตาราง `ข้อมูลพนักงาน` ในแอป แล้วตรวจว่าปัญหาที่อธิบายไว้ ยังเกิดอยู่จริงหรือไม่

#### ข้อค้นพบ 4 (จากการวิเคราะห์พื้นฐาน): 🟡 [พอใช้] คอลัมน์ Key ไม่ได้ล็อกการแก้ไข → ผู้ใช้แก้หรือคัดลอก Key ได้ ทำให้ข้อมูลอ้างอิงผิด
