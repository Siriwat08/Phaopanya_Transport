## 🧒 อ่านก่อน! ตารางนี้คืออะไร (อธิบายง่ายมาก เหมือนเล่าให้เด็ก 12 ขวบฟัง)

เป็น **สมุดจดประวัติซ่อมบำรุงรถ** — รถคันนี้เข้าซ่อมเมื่อไหร่ ทำอะไรไปบ้าง เหมือนสมุดสุขภาพของรถที่ต้องตรวจตามนัด

### 📖 คำศัพท์ที่จะเจอในไฟล์นี้ (แปลเป็นภาษาธรรมดา)

| คำเทคนิค | แปลง่าย ๆ ว่า |
|---|---|
| สูตร (Formula) | โจทย์คณิตที่พิมพ์ไว้ล่วงหน้าให้แอปคำนวณเอง เหมือนตั้งโจทย์ไว้ในเครื่องคิดเลข |
| App formula | สูตรแบบ "ล็อกถาวร" — แอปคิดค่าเดียวตลอด คนพิมพ์ทับไม่ได้ (เหมือนตราประทับ) |
| Initial value | ค่าเริ่มต้นที่แอปเติมให้ก่อน แต่คนใช้ยังเปลี่ยนได้ |
| Valid_If | "ยามเฝ้าประตู" ตรวจค่าก่อนบันทึก — ไม่ผ่าน = บันทึกไม่ได้ |
| Show_If | "ม่าน" ที่เปิดเฉพาะสถานการณ์ที่กำหนด — ไม่เข้าเงื่อนไข ช่องนั้นจะซ่อน |
| Editable_If | กุญแจที่แจกเฉพาะบางคน — คนอื่นแก้ช่องนี้ไม่ได้ |
| Read-Only | ช่องที่ "ดูได้ พิมพ์ไม่ได้" |
| Ref / อ้างอิง | สายเชื่อมไปดึงข้อมูลจากแฟ้มอื่น เหมือนสายโทรศัพท์ระหว่างห้อง |
| Key | หมายเลขบัตรประชาชนของแต่ละแถว — ห้ามซ้ำ ห้ามแก้ |
| Virtual column | ช่องคำนวณสด ไม่เก็บลง Google Sheet — เหมือนจอ LED ไม่ใช่กระดาษ |
| Security filter | ฉากกั้นข้อมูล ให้แต่ละคนเห็นเฉพาะงานของตัวเอง |

**สัญลักษณ์สีที่ใช้ทั้งชุดคู่มือ:** 🔴 = ต้องรีบดู (เสี่ยงเงิน/ข้อมูลพัง) · 🟠 = ควรแก้ (ผิดตรรกะ) · 🟡 = ทำงานได้แต่ควรปรับ · ❓ = ต้องกดลองในแอปจริงเท่านั้นถึงจะรู้ · ✅ = ปกติ/ดีอยู่แล้ว · ⚪ = ช่องข้อมูลดิบ ไม่มีสูตร

## 📌 ภาพรวมตารางนี้

- **คอลัมน์ทั้งหมด:** 14 ตัว · **Actions:** 6 รายการ
- **ผลตรวจรายคอลัมน์:** 🔴 เสี่ยง 1 · 🟠 ต้องปรับปรุง 2 · 🟡 พอใช้ 4 · ❓ ต้องยืนยันในแอป 0 · ✅ ปกติ 6
- **Security filter ปัจจุบัน:** `=OR(USERROLE() = "ADMIN", [Email พนักงาน] = USEREMAIL())`
- **Update mode:** ALL_CHANGES (มี expression: `=SWITCH(USERROLE(), "ADMIN", "ALL_CHANGES", "USER","ADDS_AND_UPDATES", "READ_ONLY")`)
- **Key ของตาราง:** ID_การเข้าบำรุงรักษา
- **อ้างอิงไปตารางอื่น (Ref ออก):** ข้อมูลพนักงาน

## 🗺️ ทางเข้าแก้ไขใน AppSheet Editor (อ่านก่อนเริ่ม — สำหรับมือใหม่)

1. เปิดเบราว์เซอร์ไปที่ https://www.appsheet.com แล้วเข้าสู่ระบบด้วยบัญชีเจ้าของแอป
2. คลิก **My apps** → เลือกแอป **เผ่าปัญญาทรานสปอร์ต** → คลิกเมนู ⋮ → **Edit** (เข้าสู่ AppSheet Editor)
3. คลิกแท็บ **Data** ที่แถบซ้าย → กลุ่ม **Tables** → คลิกตาราง **ข้อมูลการเข้าบำรุงรักษา**
4. จะเห็นรายการคอลัมน์ทั้งหมด → คลิก **ไอคอนดินสอ (pencil)** หน้าคอลัมน์ที่ต้องการแก้
5. แก้ค่าตามคู่มือด้านล่าง → กด **Done** → กด **Save** ที่แถบบนขวาของ Editor (สำคัญ! ถ้าไม่ Save การแก้จะไม่ถูกบันทึก)
6. 💡 เคล็ดลับ: ก่อนแก้จริง ให้กด **⋮ ▸ Version history** ใน Google Sheet เพื่อย้อนกลับได้ และควรสำรองสูตรเดิมด้วยการคัดลอกไปไว้ในไฟล์ Notepad ก่อน

**คำเตือนก่อนแก้:**

- แก้ทีละจุด แล้วทดสอบในแอปจริงทุกครั้ง (เปิดแอปบนมือถือ/เว็บ กด Sync แล้วลองกรอกงานจริง 1 เคส)
- AppSheet แยกชื่อคอลัมน์แบบตัวพิมพ์ใหญ่-เล็ก และแยกวรรค: `StartDate` ≠ `Startdate`, `ชื่องาน` ≠ `ชื่อ งาน`
- `[X]` ใน `SELECT(ตารางอื่น[...])` คือคอลัมน์ของ "ตารางอื่น" ไม่ใช่ของตารางที่สูตรอยู่ — อย่าเผลอไปแก้ชื่อที่จริงไม่ผิด

### 2. ID_การเข้าบำรุงรักษา ✅

| คุณสมบัติ | ค่าปัจจุบัน |
|---|---|
| Type | Text |

| Initial value | UNIQUEID() |
| Read-Only | Yes |

| Key | Yes |
| Sensitive data | No |
| Searchable | No |

| หน้าสเปก (PDF) | หน้า 96 |

**สถานะ: ✅ ดี** — พบปัญหา 1 ข้อ

#### ข้อค้นพบ 1 (จากการวิเคราะห์พื้นฐาน):  [ดี] คีย์หลักสร้างด้วย UNIQUEID() ถูกต้องตามมาตรฐาน ไม่พบข้อผิดพลาด

- **หลักฐาน:** initial_value = UNIQUEID(); read_only = Yes; key = Yes; part_of_key = Yes
- **ผลต่องาน:** ใช้เป็นคีย์หลักของแถวบำรุงรักษาได้อย่างเสถียร ไม่มีความเสี่ยงชนกัน
- **วิธีแก้:** คงเดิม และควรตั้ง Required_If = TRUE ให้ครบทุกคอลัมน์ ID ในแอปเพื่อความสม่ำเสมอ

- **วิธีตรวจ:** เปิดคอลัมน์ `ID_การเข้าบำรุงรักษา` ของตาราง `ข้อมูลการเข้าบำรุงรักษา` ในแอป แล้วตรวจว่าปัญหาที่อธิบายไว้ ยังเกิดอยู่จริงหรือไม่

### 3. วันที่เข้าบำรุงรักษา 🟡

| Read-Only | No |

**สถานะ: 🟡 พอใช้** — พบปัญหา 1 ข้อ

#### ข้อค้นพบ 1 (จากการวิเคราะห์พื้นฐาน): 🟡 [พอใช้] NOW() เป็นค่า volatile ที่ถูกประทับตอนเปิดฟอร์ม ไม่ใช่ตอนกดบันทึกจริง และผู้ใช้ทั่วไปแก้ไขไม่ได้ (Editable_If = ADMIN เท่านั้น) ทำให้วันที่ผิดคงอยู่ถาวร

- **หลักฐาน:** initial_value = =NOW(); Editable_If = =USERROLE() ="ADMIN"; Read-Only = No
- **ผลต่องาน:** บันทึกบำรุงรักษาผิดวันแล้วแก้ไขไม่ได้ ทำให้รายงานรายเดือนคลาดเคลื่อน
- **วิธีแก้:** ปล่อยให้ USER แก้ได้เมื่อยังไม่มีการอนุมัติ (เช่น Editable_If = OR(USERROLE()="ADMIN", [สถานะอนุมัติ]<>"อนุมัติ") หรือใช้ช่องแยก 'วันที่บันทึกจริง') และควรมีคอลัมน์เวลาที่กดบันทึก

- **วิธีตรวจ:** เปิดคอลัมน์ `วันที่เข้าบำรุงรักษา` ของตาราง `ข้อมูลการเข้าบำรุงรักษา` ในแอป แล้วตรวจว่าปัญหาที่อธิบายไว้ ยังเกิดอยู่จริงหรือไม่

### 4. ชื่อ - นามสกุล 🟡

| คุณสมบัติ | ค่าปัจจุบัน |
|---|---|
| Type | Text |
| App formula | — |
| Initial value | =[ID_พนักงาน].[ชื่อ - นามสกุล] |
| Read-Only | Yes |
| Hidden | No |
| Key | No |
| Sensitive data | No |
| Searchable | Yes |
| Virtual? | No |
| หน้าสเปก (PDF) | หน้า 98 |

**สถานะ: 🟡 พอใช้** — พบปัญหา 3 ข้อ

#### ปัญหา 1: [🟠 ระดับ medium] คอลัมน์นี้เก็บชื่อ-นามสกุล (PII) แต่ยังไม่ได้ตั้ง Sensitive data = Yes

- **ทำไมสำคัญ:** การตั้ง Sensitive data ทำให้แอปจัดการข้อมูลส่วนบุคคลถูกหลัก PDPA — ค่าจะถูกซ่อนจากบันทึกการแชร์และการส่งออกโดยไม่ตั้งใจ
- **วิธีแก้ทีละขั้น (จุดแก้:** `Data ▸ Tables ▸ คลิกตารางนี้ ▸ คลิกไอคอนดินสอ (pencil) ที่คอลัมน์นี้`):**
   1. ในหน้าตั้งค่าคอลัมน์ มองหากลุ่ม "Column properties"
   2. สลับสวิตช์ "Sensitive data?" จาก No เป็น Yes
   3. กด "Save" ด้านบนขวา แล้วกด Save อีกครั้งที่แถบด้านบนของ Editor

- **ตรวจว่าแก้สำเร็จ:** เปิด Data > Columns > คอลัมน์นี้ ตรวจว่าช่อง Sensitive data เป็น Yes

#### ข้อค้นพบ 2 (จากการวิเคราะห์พื้นฐาน): 🟡 [พอใช้] คอลัมน์เป็นข้อมูลส่วนบุคคลแต่ไม่ได้ทำเครื่องหมาย Sensitive data = Yes

- **หลักฐาน:** Sensitive data = No
- **ผลต่องาน:** ผู้ที่เห็นตารางนี้จะเห็นข้อมูลส่วนบุคคลในไฟล์ export และในแอป
- **วิธีแก้:** ตั้ง Sensitive data = Yes

- **วิธีตรวจ:** เปิดคอลัมน์ `ชื่อ - นามสกุล` ของตาราง `ข้อมูลการเข้าบำรุงรักษา` ในแอป แล้วตรวจว่าปัญหาที่อธิบายไว้ ยังเกิดอยู่จริงหรือไม่

#### ข้อค้นพบ 3 (จากการวิเคราะห์พื้นฐาน): 🟠 [พอใช้] ค่ามาจาก [ID_พนักงาน] ซึ่งหามาจาก LOOKUP ตาม USEREMAIL(); ถ้าอีเมลของผู้ใช้ไม่มีในตารางข้อมูลพนักงาน (หรือมีอีเมลซ้ำ) คอลัมน์นี้จะว่างโดยไม่มีข้อความแจ้งเตือนใดๆ

- **หลักฐาน:** initial_value = =[ID_พนักงาน].[ชื่อ - นามสกุล]; ต้นทาง ID_พนักงาน = =LOOKUP(USEREMAIL(), "ข้อมูลพนักงาน", "Email พนักงาน","ID_พนักงาน")
- **ผลต่องาน:** บันทึกการเข้าบำรุงรักษาที่ไม่ระบุผู้ทำ/รถยนต์ ใช้ตรวจสอบย้อนหลังไม่ได้
- **วิธีแก้:** ใส่ IF(ISBLANK(...)) กันค่าว่าง และบังคับ ID_พนักงาน ให้ระบุได้ทุกบทบาท (ดูรายการ ID_พนักงาน)

**สูตรแนะนำ (คัดลอกไปวางได้ — ปรับชื่อคอลัมน์ให้ตรงแอปจริงก่อนใช้):**

```
=IF(ISBLANK([ID_พนักงาน]), "", [ID_พนักงาน].[ชื่อ - นามสกุล])
```

- **วิธีตรวจ:** เปิดคอลัมน์ `ชื่อ - นามสกุล` ของตาราง `ข้อมูลการเข้าบำรุงรักษา` ในแอป แล้วตรวจว่าปัญหาที่อธิบายไว้ ยังเกิดอยู่จริงหรือไม่

#### ปัญหา 2: [🔴 ระดับ high] คอลัมน์อีเมลถูกใช้เป็น Security filter ของตาราง แต่ Read-Only = No ผู้ใช้แก้ค่าได้

#### ข้อค้นพบ 2 (จากการวิเคราะห์พื้นฐาน): 🟠 [ต้องปรับปรุง] ค่านี้คำนวณจากข้อมูลของตารางอื่น/แถวอื่น แต่ถูกตั้งเป็น Initial value — จึงถูกคำนวณรอบครั้งตอนสร้างแถว แล้วค้างค่าเดิมตลอดไป

- **วิธีแก้:** ย้ายเป็น App formula (หรือเติม Editable initial value) ให้คำนวณใหม่ทุกครั้ง

#### ข้อค้นพบ 4 (จากการวิเคราะห์พื้นฐาน): 🟠 [ต้องปรับปรุง] Required_If = =USERROLE() ="ADMIN" เท่านั้น → ผู้ใช้ทั่วไปสร้างแถวได้โดยไม่ต้องผูกพนักงาน; LOOKUP คืนค่าแถวแรกที่เจอ ถ้าอีเมลซ้ำในข้อมูลพนักงานจะเลือกผิดคนแบบเงียบ ๆ; ไม่มี Error_Message_If_Invalid
