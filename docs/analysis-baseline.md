# ผลวิเคราะห์ที่มีอยู่แล้ว (baseline)

ก่อนเริ่มงานใหม่ **อ่านส่วนนี้ก่อน** เพื่อไม่วิเคราะห์ซ้ำและไม่ขัดแย้งกันเอง

|---|---|---|
| พอใช้ | 197 | ทำงานได้ แต่มีจุดควรปรับปรุง |
| เสี่ยง | 85 | ความเสี่ยงสูง: ข้อมูลเสียหาย/ผิดเงิน/ความปลอดภัย/สูตรพังง่าย |
| ต้องปรับปรุง | 111 | มีข้อผิดพลาดเชิงตรรกะ/ข้อมูล/ประสิทธิภาพที่กระทบผลลัพธ์ |
| ต้องยืนยันในแอป | 117 | ต่างกันเฉพาะช่องว่าง — PDF ยืนยันไม่ได้ ต้องเปิดในแอปดู |

ที่มา: ตรวจอัตโนมัติตามเกณฑ์ 304 · ทีมวิเคราะห์เชิงลึก 123 · ตรวจชื่อคอลัมน์ที่อ้างถึง 100

## บั๊กที่ยืนยันแล้วจาก PDF (27 ข้อ)

### ผิดเคสชื่อคอลัมน์ (8 ข้อ) — สูตร error จริง
`ปริ๊นใบวางบิล.ราคารวม` · `PDFพนักงาน.ราคารวม` · `สร้างเอกสาร.ราคารวม` · `สร้างเอกสาร.ราคารวมคนขับ`
→ เขียน `Startdate`/`Enddate` แต่คอลัมน์จริงคือ `StartDate`/`EndDate`

### อ้างคอลัมน์ที่ไม่มีอยู่ในขอบเขต (15 ข้อ)
เช่น `แจ้งปัญหาระหว่างวัน` อ้าง `[Email พนักงาน]` / `[DeliveryStatus]` ในขอบเขตที่ไม่มีคอลัมน์นี้

### ไวยากรณ์สูตรผิด (2 ข้อ)
- `Acknowledge_Logs.ข้อความประกาศ` — CONCATENATE มีสตริงติดกันไม่มีคั่น + comma ท้าย
- `ตารางงานประจำวัน.ลำดับแรก` — SELECT มี argument ว่าง

## ไฟล์ที่ต้องอ่าน

## ข้อควรระวัง

baseline นี้ผ่านการตรวจซ้ำแบบอัตโนมัติแล้ว (ตรวจชื่อคอลัมน์ที่อ้างถึงด้วยกฎขอบเขต)
แต่**ยังไม่เคยทดสอบกับข้อมูลจริงในแอป** — ทุกข้อควรถือเป็น "ข้อสมมติที่ตรวจสอบได้"
ไม่ใช่ "ข้อเท็จจริงที่พิสูจน์แล้ว"
