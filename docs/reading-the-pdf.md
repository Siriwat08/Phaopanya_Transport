# ⚠️ อ่านก่อน: PDF ต้นฉบับมี "กับดัก" การตัดบรรทัด

เอกสารสเปกของแอป Appsheet ถูก render เป็น PDF โดยเบราว์เซอร์ (Skia/Chrome)
ทำให้ **ค่ายาว ๆ ถูกตัดบรรทัด** และ **ข้อความใน PDF ไม่ได้บอกว่าเดิมมีช่องว่างหรือไม่**

นี่คือกับดักที่ทำให้ AI ทุกตัว (รวมถึงผู้ช่วยรอบแรก) รายงานบั๊กปลอม

## ตัวอย่างที่เจอจริง

| ข้อความใน PDF | ของจริงในแอป | ถ้าอ่านผิดจะเป็น |
|---|---|---|
| `IN([Invoice No], [_THISROW].[Invoice No])` คั่นระหว่างบรรทัด | `Invoice No` | ❌ "อ้าง `InvoiceNo` ที่ไม่มีจริง" |
| `Error_Message_If_I` + `nvalid` | `Error_Message_If_Invalid` | ❌ JSON พัง, เกณฑ์ผิดพลาดปลอม |
| `Lat/Long_ปลาย` + `ทาง_01` | `Lat/Long_ปลายทาง_01` | ❌ "อ้างคอลัมน์ที่ไม่มีจริง" |
| `Export to` + `xlsx` | `Export to xlsx` | ❌ "แอคชันเขียนคอลัมน์ผิด" |

## กฎที่ใช้ตัดสิน (เรียงตามลำดับความน่าเชื่อถือ)

### 1) เรขาคณิตของบรรทัด (ใช้ได้เสมอ)
- บรรทัดที่ **วิ่งจนเต็มขอบขวาของหน้า** → ถูกตัด **กลางคำ** → ต่อกลับ **ห้ามเว้นวรรค**
- บรรทัดที่ **หยุดก่อนขอบ** → ถูกตัด **ที่ช่องว่างจริง** → ต่อกลับ **ต้องเว้นวรรค**

> ใน PDF ของแอปนี้ ขอบขวาอยู่ที่ประมาณ x ≈ 549 pt (กระดาษ A4)
> ใช้เกณฑ์ "ห่างจากขอบไม่เกิน ~14pt ถือว่าเต็ม" (ทดสอบกับ JSON 2,304 ชุดแล้วได้ 0 key ที่พัง)

### 2) ต้องมีหลักฐานจากพิกัดคำก่อนซ่อมชื่อ
ถ้าจะแก้ชื่อคอลัมน์ที่ "หายไป" ต้องยืนยันว่า **PDF ตัดบรรทัดตรงนั้นจริง**
(คำสุดท้ายของบรรทัด N + คำแรกของบรรทัด N+1 ต้องประกอบกลับเป็นชื่อนั้นได้)
ถ้าต่อกลับไม่ได้ → ห้ามซ่อม ให้รายงานเป็น *"ต้องยืนยันในแอป"*

### 3) ช่องว่างเท่ากับระยะวรรคของอักษรไทย
อักษรไทยในฟอนต์นี้กินความกว้าง **2.97 pt** เท่ากับช่องว่างพอดี
→ **มองด้วยตาแยกไม่ได้ว่าชื่อคอลัมน์ที่ต่างกันเป็นช่องว่างจริงหรือจุดตัดคำ**
→ ข้อสรุปที่ต่างกันด้วยเคส = บั๊กจริง · ต่างกันด้วยช่องว่าง = ยังไม่รู้

### 4) แยก "ต่างเคส" ออกจาก "ต่างช่องว่าง" เสมอ
Appsheet แยกเคสชื่อคอลัมน์ → `Startdate` vs `StartDate` = **error จริง 100%**
แต่ `Shipment No` vs `ShipmentNo` = ยังยืนยันไม่ได้

### 5) ขอบเขต (scope) สำคัญกว่าตัวอักษร
การอ้างคอลัมน์ในแอปมีขอบเขตตามไวยากรณ์ — ถ้าไม่แก้ scope ให้ถูก
**ทุกความต่างด้านเคสในแอปจะดูเหมือนบั๊ก** (รอบแรกของงานนี้เจอบั๊กปลอม 4 ข้อจาก 22 ข้อที่ "ยืนยันแล้ว")

## ตัวอย่างขอบเขต

```
=ANY( SELECT(ตารางงานประจำวัน[ID_งานประจำวัน],
              [Invoice No] = IF(ISNOTBLANK([Scan_Invoice]), [Scan_Invoice], [Select_Invoice]) ) )
```
- `ตารางงานประจำวัน[...]` → ตารางงานประจำวัน
- `[Invoice No]` → **ตารางงานประจำวัน** (อยู่ใน SELECT)
- `[Scan_Invoice]`, `[Select_Invoice]` → **ตารางงานประจำวัน** เช่นกัน → แต่สองคอลัมน์นี้อยู่ในตาราง ScanDocs
  → นี่คือบั๊กจริง (หรือเป็นการอ้างผิดตาราง) — ต้องแก้เป็น `[_THISROW].[...]` หรือย้ายออกจาก SELECT

## ถ้าคุณมี PDF ต้นฉบับ

ไฟล์ PDF 1,946 หน้า **ไม่ได้อยู่ใน repo นี้** (ใหญ่ + มีข้อมูลส่วนบุคคล)
ขอจากเจ้าของแอปได้ แล้วใช้คำสั่งนี้เพื่อดูพิกัดคำที่ต้องการ:

```bash
pdftotext -bbox-layout "Application Documentation.PDF" bbox.xml
python3 - <<'PY'
import re, html
s = open("bbox.xml", encoding="utf-8").read()
for page_no, m in enumerate(re.finditer(r'<page width="[\d.]+" height="[\d.]+">(.*?)</page>', s, re.S), 1):
    print("PAGE", page_no)
    for line in re.finditer(r'<line [^>]*>(.*?)</line>', m.group(1), re.S):
        words = [html.unescape(t) for t in re.findall(r'<word [^>]*>(.*?)</word>', line.group(1))]
        print("   ", " ".join(words))
PY
```

จากนั้นใช้ **xMin/xMax ของคำสุดท้ายในบรรทัด** เทียบกับขอบขวาของหน้า เพื่อตัดสินใจว่าเป็นการตัดคำกลางคำหรือตัดที่ช่องว่าง
